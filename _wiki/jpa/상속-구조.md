# @Inheritance 전략

1. 각각의 테이블로 변환 (Joined Strategy)
- 엔티티 각각을 테이블로 만들고 자식 테이블이 부모 테이블의 기본 키를 받아서 **기본 키 + 외래 키**로 사용하는 전략이다.
- 타입을 구분하는 컬럼을 추가해야 한다. 기본적으로 DTYPE 컬럼을 구분 컬럼으로 사용
- **가장 많이 사용됨**
- 장점
  - 테이블이 정규화된다
  - 외래키 참조 무결성 제약조건을 활용할 수 있다
  - 저장공간을 효율적으로 사용
- 단점
  - 조회할 때 조인이 많이 사용되어 성능이 저하될 수 있다
  - 조회 쿼리가 복잡하다
  - 데이터를 등록할 INSERT SQL을 두 번 실행한다
        ```java
        @Entity
        // 부모 클래스에 @Inheritance 사용
        @Inheritance(strategy = InheritanceType.JOINED) 
        // 이 컬럼으로 자식 테이블 구분
        @DiscriminatorColumn(name = "DTYPE") 
        public abstract class Item {
          @Id @GeneratedValue
          private Long id;
          private String name;
        }

        @Entity
        @DiscriminatorValue("A")
        public class Album extends Item {
          private String artist;
        }

        @Entity
        @DiscriminatorValue("B")
        @PrimaryKeyJoinColumn(name = "book_id") // id 재정의
        public class Book extends Item {
          private String artist;
        }
        ```

    1. 통합 테이블로 변환 (JPA 단일 테이블 전략)
        - 조회할 때 조인을 사용하지 않으므로 일반적으로 가장 빠르다
        - 자식 엔티티가 매핑한 컬럼은 모두 Nullable 이어야 한다
        - 장점
            - 조인이 필요 없어서 조회 성능이 빠르고 단순하다.
        - 단점
            - 자식 엔티티가 매핑한 컬럼은 모두 null 을 허용해야 한다
            - 테이블이 커질 수 있다
        
        ```java
        @Entity
        // 부모 클래스에 @Inheritance 사용
        @Inheritance(strategy = InheritanceType.SINGLE_TABLE) 
        // 이 컬럼으로 자식 테이블 구분
        @DiscriminatorColumn(name = "DTYPE") 
        public abstract class Item {
          @Id @GeneratedValue
          private Long id;
          private String name;
        }
        
        @Entity
        @DiscriminatorValue("A")
        public class Album extends Item {
          private String artist;
        }
        
        @Entity
        @DiscriminatorValue("B")
        public class Book extends Item {
          private String artist;
        }
        ```
        
    2. 서브타입 테이블로 변환 (JPA 테이블 전략)
        - 자식 엔티티마다 테이블을 만든다.
        - 구분 컬럼을 사용하지 않는다.
        - **일반적으로 추천하지 않는다**
        - 장점
            - 서브 타입을 구분해서 처리할 때 효과적
            - not null 제약조건 사용 가능
        - 단점
            - 여러 자식 테이블을 함께 조회할 때 성능이 느리다. (SQL에서 UNION 사용)
            - 자식 테이블을 통합해서 쿼리하기 어렵다
        
        ```java
        @Entity
        @Inheritance(strategy = InheritanceType.TABLE_PER_CLASS)
        public abstract class Item {
          @Id @GeneratedValue
          private Long id;
          private String name;
        }
        
        @Entity
        public class Album extends Item {
          private String artist;
        }
        
        @Entity
        public class Book extends Item {
          private String artist;
        }
        ```

# @MappedSuperclass

- 부모 클래스는 테이블과 매핑하지 않고 부모 클래스를 상속받는 자식 클래스에게 **매핑 정보만 제공. 즉 단순히 매핑 정보를 상속하는 추상 클래스 목적**
- 관련 어노테이션
    - @AttributeOverride 매핑정보 재정의
    - @AssociationOverride 연관관계 재정의
